# 威胁模型（Threat Model）

> 对应 PRD §28/§39。本文覆盖全项目攻击面，是 [wallet-security.md](wallet-security.md) 的上位文档：
> 前者讲「怎么实现」，本文讲「防的是谁、防到什么程度、还剩什么风险」。

## 1. 范围与前提

- **在范围内**：Android 客户端（本仓库全部代码）、Keystore 使用方式、RPC/聚合器/行情服务等外部依赖的信任假设
- **不在范围内**：钱包智能合约、DEX/桥协议自身安全性、用户设备固件的底层漏洞、交易所/法币通道
- **前提**：ChainFlow 是**非托管教育项目**，用户对助记词负最终责任；不存在任何服务端托管或恢复通道

## 2. 资产清单

| ID | 资产 | 载体 | 泄露/被篡改后果 |
|---|---|---|---|
| A1 | 助记词（12 词） | 内存瞬时窗口 / Keystore 密文 | **全链资产永久丢失**（不可撤销） |
| A2 | 派生私钥（secp256k1 / ed25519） | 内存瞬时窗口（不落盘、不缓存） | 同上 |
| A3 | 签名意图（to / amount / calldata） | 内存 / UI | 被篡改 = 用户签了不想签的交易 |
| A4 | 钱包地址 | EncryptedPrefs 明文 | 公开信息；泄露影响隐私（可关联持仓） |
| A5 | 剪贴板内容 | 系统剪贴板 | 后台应用可读 → 地址被替换（address swap） |
| A6 | 交易历史 / 余额 | Room / 内存 | 泄露持仓与行为画像 |
| A7 | 应用完整性 | APK / 运行时 | 被重打包后窃取 A1 |

## 3. 信任边界

```
┌────────────────────── 设备（不可信度：中）──────────────────────┐
│                                                                  │
│  ┌──── UI (Compose) ────┐    ┌──── 系统窗口 ────┐                │
│  │ 明文助记词仅在此渲染  │    │ BiometricPrompt  │                │
│  └─────────┬────────────┘    └──────────────────┘                │
│            │ UiIntent                                            │
│  ┌─────────▼──────────── ViewModel / Repository ───────────────┐ │
│  │ 助记词明文：解密 → 派生 → 签名 → 丢弃（无字段缓存）           │ │
│  └─────────┬───────────────────────────────┬───────────────────┘ │
│            │ Credentials(内存)              │ 密文                 │
│  ┌─────────▼──────────┐          ┌─────────▼──────────────┐       │
│  │ blockchain:evm/sol │          │ EncryptedPrefs (SP)    │       │
│  └─────────┬──────────┘          └─────────┬──────────────┘       │
│            │                               │ AES-256/GCM 密文      │
│            │                    ┌──────────▼──────────┐           │
│            │                    │ Android Keystore(TEE)│ ← 密钥不可导出
│            │                    └─────────────────────┘           │
└────────────┼─────────────────────────────────────────────────────┘
             │ 已签名交易（不含私钥）/ 查询请求（含地址）
   ┌─────────▼──────────┐   ┌──────────────┐   ┌────────────────┐
   │ 公共 RPC 节点       │   │ Li.Fi 聚合器 │   │ Binance vision │
   │ （不可信，可作恶）   │   │ （不可信）    │   │ （只读行情）    │
   └────────────────────┘   └──────────────┘   └────────────────┘
```

关键结论：**签名在设备内完成**，外部服务永远拿不到私钥；但外部服务能拿到**地址、金额、交易意图**（隐私面），也能返回**错误的 calldata**（完整性面，需用户在预览中确认）。

## 4. 攻击者模型

| ID | 攻击者 | 能力 | 典型动机 |
|---|---|---|---|
| P1 | 恶意应用（同设备） | 读剪贴板、截屏、后台联网；无 root 权限 | 替换收款地址、窃取助记词截图 |
| P2 | 物理接触者 | 解锁屏幕、查看最近任务缩略图 | 窥屏、相册翻找截图 |
| P3 | Root / 注入攻击者 | Hook 进程、dump 内存、修改返回值 | 直接窃取派生后的私钥 |
| P4 | 网络中间人 | 篡改 HTTP 响应（若 TLS 被绕过）、DNS 劫持 | 换 calldata / 换 quote |
| P5 | 恶意 RPC 节点 | 返回伪造余额、伪造 receipt、拒绝服务 | 诱导用户超额转账、隐藏失败 |
| P6 | 恶意聚合器 / DApp | 返回恶意 calldata、超滑点交易 | 授权钓鱼、抽干余额 |
| P7 | 供应链 | 依赖包被投毒、构建产物被替换 | 大规模窃取 |

## 5. 威胁与缓解（现状）

### T1 助记词明文落盘

| 项 | 内容 |
|---|---|
| 路径 | 开发者误用 SP/Room/文件存明文；日志打印 |
| 影响 | A1 泄露，资产永久丢失 |
| 现状 | ✅ 已缓解：`EncryptedPrefs` 只存 Keystore 密文；`SecurityGuard.logSecure()` 空实现（**任何构建都不输出**敏感日志）；数据库无密钥字段 |
| 残余 | 无（假设代码不被篡改） |

### T2 内存中的私钥（P3）

| 项 | 内容 |
|---|---|
| 路径 | root 后 `ptrace`/Frida hook、heap dump |
| 影响 | A2 泄露 |
| 现状 | 🟡 部分缓解：不缓存 `Credentials`、每次重新解密派生、派生在 `Dispatchers.Default`；`unlock()` 返回的对象作用域局限在单次调用 |
| 残余 | **JVM 无法保证 String/ByteArray 被及时清零**，GC 前仍可能在堆中；root 设备上无法防御 hook。文档明确「不承诺抵抗 root 环境」 |

### T3 设备被 root / 模拟器

| 项 | 内容 |
|---|---|
| 现状 | ❌ 未实现 root/emulator 检测（PRD §28「建议」项） |
| 缓解 | 依赖 Android Keystore：密钥材料不可导出，即使 root 也拿不到原始 AES key；但**能拿到内存中的解密结果** |
| 建议 | 引入 `Play Integrity API` + 自建 root 特征检测；检测到高风险环境时禁用签名并提示（不要只警告） |

### T4 运行时 Hook / 重打包（P3/P7）

| 项 | 内容 |
|---|---|
| 现状 | ❌ 无 Frida 检测、无签名校验、无完整性自检 |
| 缓解 | Release 开启 R8（`optimization.enable = true`）提高逆向成本；无调试符号 |
| 建议 | 校验 `PackageManager` 签名摘要与预期一致；检测 `frida-server` 端口/进程名；Play Integrity 强校验 |

### T5 截屏 / 录屏 / 最近任务缩略图（P1/P2）

| 项 | 内容 |
|---|---|
| 路径 | 助记词页被截图，或后台任务快照被读取 |
| 现状 | ✅ 助记词展示阶段（`Stage.BACKUP`）启用 `FLAG_SECURE`，离开阶段立即清除 |
| 残余 | Send 预览、Swap 确认、钱包总览**未**加 FLAG_SECURE（用户可能需要截图分享 txHash）；私钥不在这些页面 |

### T6 剪贴板窃取与地址替换（P1）

| 项 | 内容 |
|---|---|
| 路径 | 用户复制地址 → 恶意应用读剪贴板并替换 → 用户粘贴到 Send |
| 现状 | 🟡 复制后 45s 自动 `clearPrimaryClip()`，缩短窗口期；地址在 UI 上完整展示 |
| 残余 | 45s 内仍可被读取；**粘贴时未做地址来源校验**；无地址簿/白名单 |
| 建议 | 粘贴时显示「地址来自剪贴板，请核对首尾 6 位」；引入地址簿与 ENS/校验和显示（EIP-55） |

### T7 交易意图篡改（P4/P5/P6）

| 项 | 内容 |
|---|---|
| 路径 | RPC/聚合器返回伪造 calldata；用户盲签 |
| 现状 | 🟡 Swap 预览只展示 `fromSymbol/fromAmount/toSymbol/toAmount/rate/gas`，**不展示实际 to 地址与 calldata 解码结果**；Send 只允许原生币转账（`value` + 空 data），语义明确 |
| 残余 | 恶意 Li.Fi 响应可让用户签下「授权无限额度」或「转给攻击者」的合约调用而无法从 UI 察觉 |
| 建议 | 预览中固定展示 `to`（合约名/地址首尾）、`value`、函数选择器（`0x095ea7b3` = approve 必须显式告警）、滑点上限；对大额交易强制二次输入 |

### T8 Li.Fi / 聚合器信任（P6）

| 项 | 内容 |
|---|---|
| 现状 | 🟡 报价与 calldata 全部来自 Li.Fi（免 Key 公共端点），无本地交叉校验 |
| 残余 | 单点信任；`toolName` 仅用于展示；不验证 `approvalAddress`/`permit2` 数据 |
| 建议 | 多源报价对比（1inch/0x）、对 `approve` 强制限额（`approve(spender, amount)` 而非 `MaxUint256`）、校验 `to` 是否在白名单路由合约内 |

### T9 RPC 节点作恶（P5）

| 项 | 内容 |
|---|---|
| 路径 | 伪造 `eth_getBalance`（诱导大额转账）、伪造 receipt（隐藏失败）、返回错误 `chainId` |
| 现状 | 🟡 使用公共 RPC（`sepolia.base.org` 等）；单端点、无 failover、无响应交叉校验（PRD §21 的 failover 列为后续） |
| 残余 | 交易签名本身安全（EIP-155 chainId 绑定网络），但**状态展示可被欺骗** |
| 建议 | 多 RPC 比对余额/回执；关键交易前用第二个端点复核 nonce/gas；增加 RPC 响应签名/证书校验（见 T10） |

### T10 网络层（P4）

| 项 | 内容 |
|---|---|
| 现状 | ✅ `usesCleartextTraffic=false`（仅 HTTPS/WSS）；OkHttp 默认 TLS 校验 |
| 残余 | ❌ 无证书 pinning（PRD §28 建议项）；用户设备被安装恶意 CA 时可被中间人 |
| 建议 | 对 `li.quest`、RPC 域名做 `CertificatePinner`（注意证书轮换会导致旧版本失效，需备选 pin） |

### T11 备份与恢复

| 项 | 内容 |
|---|---|
| 现状 | ✅ `allowBackup=false` + `dataExtractionRules`（云备份/设备迁移不带走密文）；密文离开设备即无意义（Keystore key 不可迁移） |
| 残余 | 用户自行截屏/抄写助记词的泄露不在 App 控制范围内 |

### T12 生物识别绕过

| 项 | 内容 |
|---|---|
| 现状 | 🟡 `BIOMETRIC_WEAK \| DEVICE_CREDENTIAL`；**无生物识别设备时直接放行签名**（MVP 决策）；Keystore 密钥**未绑定用户认证**（无 `setUserAuthenticationRequired`） |
| 残余 | 设备无锁屏/无生物识别时，任何拿到已解锁设备的人都能签名；root 后可直接调用 `unlock()` 绕过 Prompt（因为认证与密钥解密是两条独立路径） |
| 建议 | Phase 6：Keystore 密钥加 `setUserAuthenticationRequired(true)` + `setInvalidatedByBiometricEnrollment(true)`，让「认证」成为解密的**必要条件**而非 UI 门禁；无生物识别时强制应用内 PIN |

> 这是本项目**最值得优先修复**的安全设计缺口：当前生物识别是「UI 层门禁」，不是密码学约束。

### T13 日志 / 崩溃上报

| 项 | 内容 |
|---|---|
| 现状 | ✅ 无 Analytics SDK；敏感路径走 `logSecure()`（空实现）；`SwapRepository` 仅记录错误摘要 |
| 残余 | 第三方库（OkHttp/web3j）在异常栈中可能带请求体；未接入崩溃上报，故暂无外传通道 |

### T14 本地数据泄露（P1/P2）

| 项 | 内容 |
|---|---|
| 现状 | 🟡 Room 明文存交易历史（地址/金额），依赖系统沙箱 + 设备加密（FBE） |
| 残余 | root 后可读；未做数据库加密（SQLCipher） |
| 建议 | 对隐私敏感字段做应用层加密，或启用 SQLCipher（注意性能与迁移成本） |

### T15 隐私元数据

| 项 | 内容 |
|---|---|
| 路径 | 公共 RPC 与 Li.Fi 都能看到「地址 + 时间 + 金额 + 目标合约」 |
| 现状 | 🟡 无自建节点/代理；地址直接作为 `fromAddress` 发送 |
| 残余 | 可被第三方聚合为持仓与行为画像 |
| 建议 | 支持自定义 RPC（用户自带节点）；文档中明确声明「默认公共端点会看到你的地址」 |

## 6. STRIDE 速查

| 类别 | 对应威胁 | 主要控制 |
|---|---|---|
| Spoofing | T4、T9 | 签名校验（未实现）、RPC 多源复核 |
| Tampering | T7、T10 | EIP-155 chainId、calldata 预览（部分）、TLS |
| Repudiation | — | 链上交易天然不可否认；本地历史仅作展示 |
| Information disclosure | T1、T2、T5、T6、T14、T15 | Keystore、不缓存私钥、FLAG_SECURE、剪贴板超时 |
| Denial of service | T9 | RPC failover（未实现） |
| Elevation of privilege | T3、T4、T12 | root 检测（未实现）、认证绑定密钥（未实现） |

## 7. 明确的安全声明（写入 README 的边界）

1. **不承诺抵抗已 root / 被注入的设备**。这类环境下任何非托管钱包都无法保证私钥安全。
2. **不托管、不找回**：助记词丢失即资产丢失，App 无任何后门恢复通道。
3. **公共 RPC / 聚合器会看到你的地址与交易意图**，本项目不做隐私增强（无 Tor/自建节点）。
4. **Swap 的最终 calldata 来自第三方聚合器**，签名前请核对预览中的关键字段。
5. MVP 未实现：root/模拟器检测、证书 pinning、Play Integrity、Keystore 认证绑定、数据库加密、多源报价校验。

## 9. 演进路线（按风险/成本排序）

1. **Keystore 密钥绑定用户认证**（消除 T12 的密码学缺口）
2. **签名前 calldata 解码预览 + approve 限额告警**（T7）
3. **RPC 多端点 failover 与交叉校验**（T9，同时满足 PRD §21）
4. **地址校验和展示 + 粘贴来源提示**（T6）
5. **证书 pinning + Play Integrity**（T4/T10）
6. **数据库加密**（T14）
7. **root/模拟器风险分级**：高风险仅只读、禁止签名
